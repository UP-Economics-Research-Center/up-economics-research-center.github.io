Editing and approval

UP Economics Research Center

For editors

  1. Sign in with your invited GitHub account. Open the collection and record you want to edit. The invitation must have been accepted.
  2. Edit both English and Spanish fields. Keep UP Economics Research Center unchanged in both languages. Article titles, author names and journal names keep their original wording.
  3. Review the content preview. Check names, affiliations, dates, links and images against their sources. A source URL and verification date help the reviewer. This preview shows content, not the complete website layout.
  4. Choose Save to keep a draft. The public site stays unchanged. Move the entry to In review when ready for another person to check it.
  5. If changes are requested, revise the same draft and save again. New edits need another review.
  6. Check that the build passes and request another person’s review. Non-administrators need one GitHub approval before publishing. Administrators may merge without that approval, including their own pull request, using GitHub’s administrator override. The public site updates after deployment succeeds.

Visibility is separate from publication. “Include on website” means the record may appear after its pull request is merged and deployed. Keep it on while editing an existing public record. Turn it off only when you intend to hide that record in the next publication. Setting it on does not publish a draft; Ready is not a GitHub approval or a merge.

For reviewers

Open the proposed change in GitHub’s review queue ↗. Compare both languages, sources, author relationships, image credits and visibility settings. Approve the exact version you reviewed or request changes. GitHub does not allow anyone to approve their own pull request. An administrator’s merge override is an exception to the approval requirement, not self-approval. Independent review remains recommended; check the build before any merge.

The review workflow saves a downloadable editorial-site-preview artifact in the proposed change’s build run. This contains the generated website files; it is not an automatically hosted preview link. A maintainer can open a local preview for visual review. No review build publishes to the live site.

Images and current projects

Use an article’s first PDF page or an approved journal-page capture as its small publication image. Upload the image, add alternative text in both languages, and record the credit and source. Current projects keep their saved order; optional images sit beside the text. Without a photo, a project uses the full row. Do not add a placeholder just to fill space.

If publication fails

A missing translation, broken reference or unavailable image may stop the build. Correct the draft and request review again. If approval is missing, ask another invited reviewer or an administrator to review the change. The administrator may choose to merge using the exception described above. If the change is merged but deployment fails, contact a maintainer; saving another unrelated change is not the fix.

Para editar

  1. Inicia sesión con tu cuenta de GitHub invitada y abre el registro que quieres editar. Debes haber aceptado la invitación.
  2. Completa los campos en inglés y español. Conserva UP Economics Research Center en ambos idiomas, sin traducir. Los títulos de artículos, nombres de autores y revistas se mantienen en su idioma original.
  3. Revisa el contenido, las imágenes, los datos y sus fuentes en la vista previa. Esa vista muestra el contenido; el diseño completo se revisa en una vista previa del sitio.
  4. Usa Save para guardar un borrador. El sitio público no cambia. Pasa el registro a In review cuando esté listo para que otra persona lo revise.
  5. Si te piden cambios, edita el mismo borrador y guárdalo. Los cambios nuevos necesitan otra revisión.
  6. Comprueba que pase la generación y solicita la revisión de otra persona. Quien no sea administrador necesita una aprobación en GitHub antes de publicar. Los administradores pueden hacer merge sin esa aprobación, incluso de su propio PR, usando la excepción administrativa de GitHub. El sitio se actualiza cuando termina correctamente el despliegue.

Visibilidad no significa publicación. “Mostrar en el sitio” permite que el registro aparezca después del merge y despliegue de su PR. Mantén el interruptor activado al editar un registro que ya es público. Desactívalo solo si quieres ocultarlo en la siguiente publicación. Activarlo no publica un borrador; Ready no equivale a una aprobación de GitHub ni a un merge.

Para aprobar

Abre el cambio propuesto en la cola de revisiones de GitHub ↗. Comprueba ambos idiomas, fuentes, autores, imágenes y visibilidad. Aprueba la versión exacta revisada o solicita correcciones. GitHub no permite a nadie aprobar su propio PR. La excepción que permite a un administrador hacer merge no es una autoaprobación. La revisión independiente sigue siendo recomendable; comprueba la generación antes de cualquier merge.

La comprobación de revisión guarda el sitio generado como archivo descargable editorial-site-preview; no es un enlace de vista previa alojada. Un responsable puede abrirlo localmente para revisar el diseño. La comprobación no publica el sitio.

Imágenes y proyectos actuales

Usa la primera página del PDF o una captura aprobada de la revista como miniatura. Agrega texto alternativo en ambos idiomas, crédito y fuente. Los proyectos conservan su orden; la imagen es opcional y, sin foto, el texto ocupa la fila completa.

Si no se puede publicar

Corrige traducciones faltantes, referencias o imágenes en el mismo borrador y solicita otra revisión. Si falta aprobación, pide la revisión a otra persona invitada o a un administrador. Este último puede decidir hacer merge usando la excepción explicada arriba. Si el cambio ya fue integrado pero falla el despliegue, consulta a un responsable.
